Cleaning the WordPress database without breaking the site

The tables every page reads grow with revisions, expired transients, orphaned post meta and spam. Removing what is provably unused is safe; removing what a plugin still expects is how sites lose settings. Cinder Page Cache limits itself to the first category and reports the byte count before it deletes anything.

Download plugin.zipWhat Cinder Page Cache does

Safe: expired transients and orphaned meta

Transients have a lifetime and WordPress already expects them to vanish. Meta rows whose parent post no longer exists are read by nothing. Both are deleted without touching configuration.

Careful: tables belonging to other plugins

Analytics, form entries, e-commerce orders and logs are not junk, even when they are large. Cinder Page Cache does not touch a table it did not create; if a plugin's table is huge, that plugin owns the retention policy.

Take a copy first

Any cleanup should start with an export. Cinder Page Cache can write a SQL dump of the affected tables to your uploads directory before deleting, so the state is recoverable without a full-site restore.

Watch the ratio rather than the total: hits divided by requests, over a day. A cache that serves 60% of requests is doing something; 95% means it is covering the site. The same screen shows cache size and the oldest entry, which tells you whether the TTL matches how often the content actually changes.

If the ratio is high and the site still feels slow, the problem is downstream of PHP: images, fonts, or a host network that is saturated. That is the point at which a CDN becomes the right answer, and the counters here are how you know you have reached it.

Who this is for

The useful test: do you administer the site yourself, and does it run on hosting you can restart? If yes, Cinder Page Cache is the whole performance stack. If someone else owns the platform and the CDN, the plugin is a smaller piece of a larger puzzle and the counters here will tell you how much of the problem was yours to begin with.

What it does not do

No CDN. No image CDN. No edge computing, no page builder, no backup, no security firewall. Cinder Page Cache does not rewrite your theme, does not inject a dashboard banner asking for a review, and does not phone home unless the administrator ticks the box on the dashboard. If a feature needs a remote service to work, it does not belong in a cache plugin.

Frequently asked

Will cleanup speed up my site?

It shortens queries on the tables it cleans. Expect a small but real gain, larger on old sites with tens of thousands of revisions.

Can I delete all revisions?

Yes, but keeping a few per post costs almost nothing and preserves editorial history.

Does it touch other plugins' tables?

No. Only rows and tables Cinder Page Cache created or WordPress marked as disposable.
